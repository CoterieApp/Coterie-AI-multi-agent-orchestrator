# Contributing feedback and documentation

Coterie is in private beta. This repository accepts bug reports, feature requests and improvements to public documentation. Application development happens privately.

## Before opening an issue

- Search existing issues for the same problem.
- Use the bug or feature-request form and describe a concrete workflow.
- Include the Coterie build, Windows version and relevant official CLI versions.
- Remove credentials, private source code, customer information and identifying file paths.
- Report potential vulnerabilities using [SECURITY.md](SECURITY.md).

Access requests and installation details specific to your account belong at [coterie@offlinestudio.eu](mailto:coterie@offlinestudio.eu). An issue does not register you for the beta.

## Documentation pull requests

Keep a pull request focused and explain which instruction or claim it corrects. Use relative links between documents and check every changed link. Product claims must reflect a verified feature, a stated limitation or an explicitly labelled proposal.

Do not add application source, binaries, real workspace data, debug dumps, provider credentials or internal engineering plans. New public code samples require maintainer agreement on scope and licensing before inclusion.

For code changes, follow the project coding guidelines provided by the maintainers and [maintenance rules](docs/maintenance.md).

## Community conduct

Be respectful and specific. Critique ideas and behaviour without personal attacks. Do not post unsolicited promotions, harassment or other people's private information. Maintainers may close duplicates, off-topic requests or abusive threads.
